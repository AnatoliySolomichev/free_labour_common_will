# Соревнования: правила по хешу, раунды, попытки, вердикты (ИР-026)

**Статус:** черновик v0.1 (2026-10-23).
**Назначение:** второй сценарий ИР-026 — соревнования по упражнениям на видео — на той же заметке о предмете, что и соцслой (records.md §8.11, social.md §2). Нумерация разделов — своя (CLAUDE.md).

---

## 1. Назначение

Люди со своими цепями делают подтягивания, отжимания и т. п. и снимают видео. Судьи из выбранного круга засчитывают повторы записями в **своих** цепях. Таблицу каждый считает сам, глазами своего круга: у накрутчика с подставными судьями в его собственном кругу своя таблица, а ферма ботов в чужом кругу весит ноль.

Здесь впервые появляется то, с чего начался ИР-026, — **правила деятельности как запись, опознаваемая по хешу**, к которой присоединяются согласием. Решения участника 2026-10-23:

- видео — ключ по хешу исходного файла, копии на площадках — заметки «тот же предмет» (contests.md §4);
- маяк — раунд, заметка организатора: начало хеша её блока показывают в кадре (contests.md §3);
- судьи — круг смотрящего, итог попытки — медиана вердиктов (contests.md §6);
- идентификатор соревнования — хеш содержания правил, вступление — согласие с ними (contests.md §2).

Новых типов записей нет: виды `round`, `attempt`, `verdict`, `same` той же заметки и `Concept` для правил.

## 2. Правила — мягкий протокол

**Запись правил** — `Concept` с тегами, как профиль (records.md §8.6):

```
Concept{ text: "Подтягивания на турнике
                Подбородок выше перекладины, внизу руки полностью прямые. …",
         tags: ["kind:contest", "unit:повтор", "better:more", "agg:median"] }
```

- `text` — правила для людей, первая строка — название. Что засчитывать, решают судьи по этому тексту.
- Параметры — **конфигурация готовых блоков**, первая ступень мягкого протокола из ИР-026: `unit` — единица результата (подпись), `better` — `more` или `less`, в какую сторону лучше, `agg` — как сводить вердикты (пока только `median`).

**Идентификатор соревнования — хеш содержания правил:** `b2:` и BLAKE2b-256 записи в детерминированном CBOR (social.md §3.5). Одинаковые байт в байт правила — одно соревнование, где бы они ни лежали; любая перестановка тегов — уже другое.

- **Копия правил** (`bc contest adopt`) — тот же `b2:…`; хозяин копии может открывать свои раунды. Это «кто принял — тот хранит» из ИР-026.
- **Вступление — согласие** (`Consent`, records.md §8.10) с блоком правил, любой их копией; подпись под своими правилами — уже согласие. Выйти — согласием с `agreed = false`: действует последнее слово.
- В таблицу идут попытки и вердикты **только согласившихся**: судья, не принявший правил, судит по каким-то другим.

## 3. Раунд и маяк

**Раунд** — заметка организатора:

```
Note{ about: "b2:<правила>", kind: "round", re: <свой блок правил>, text: "Октябрь" }
```

Раунд действителен, только если блок правил лежит **в цепи того, кто открыл раунд**, и его содержание хешируется в `b2:` соревнования: иначе раунд чужого соревнования открыл бы любой, не имея его правил.

**Маяк — хеш блока раунда.** До записи раунда его не знал никто; первые 6 знаков спортсмен показывает в кадре — значит, видео снято не раньше раунда. «Не позже» — время блока попытки и слияния (blockchain.md §5.2). Виден ли маяк в кадре, проверяют судьи глазами, по тексту правил. Организатор мог заранее шепнуть маяк другу — от этого защищает только доверие к организатору раунда.

Попытка пишется о раунде, таблица считается по раунду. У одного соревнования может быть много раундов многих организаторов.

## 4. Попытка и видео

```
Note{ about: <блок раунда>, kind: "attempt", re: "b2:<хеш файла>", v: 20,
      from: 5, to: 70, text: "маяк a3f9c2 в кадре" }
```

- `re` — **видео: ключ `b2:` по хешу исходного файла** (social.md §3.5). Можно назвать и ключ площадки или блок, но таблица пометит «видео без хеша файла».
- `v` — заявленный результат; `from`/`to` — где в видео подход; `text` — заметка.
- **Видео в цепь не кладётся** (так решён вопрос blockchain.md §11.6): хеш фиксирует файл, подменить его нельзя — `bc contest verify` сверит любой файл с попыткой.
- **Копии — «тот же предмет»:** `Note{about: "b2:…", kind: "same", re: "yt:…"}`; записать копию может кто угодно. YouTube перекодирует, и его копия с хешем не совпадёт: ссылка — удобство, доказательство — исходный файл.
- Раунд и попытка — **по одной в блоке**: на них ссылаются попытки и вердикты (records.md §2). Копии можно писать списком.

## 5. Вердикт

```
Note{ about: <блок попытки>, kind: "verdict", v: 18, from: 12, to: 71,
      text: "2 без полной амплитуды" }
```

- `v` — засчитано, не меньше нуля; `from`/`to` — где судья считал; `text` — замечания.
- **Последнее слово судьи** (records.md §8.11): передумал — новый вердикт.
- **Себе не судья:** вердикт спортсмена о своей попытке не считается, клиент его и не запишет.

## 6. Таблица раунда

`bc contest table РАУНД` считает клиент, как картину соцслоя (social.md §6):

- **Судьи — ваш круг** (social.md §5): вы, шаг 1, а с `--hops 2` — шаг 2; цепи из игнора — нигде. С `--all` — все согласные с правилами: так видно, зачем круг — без него ферма засуживает сама себя на первые места.
- **Согласные** — хозяева копий правил, известных по раундам соревнования, и записавшие согласие с любой из них.
- **Итог попытки — медиана вердиктов.** При чётном числе судей берётся та из двух средних, что хуже для спортсмена: сомнение — не в пользу попытки.
- **Место — по лучшей попытке спортсмена:** по итогу в сторону `better`; при равенстве — больше судей, потом раньше.
- Отдельно, числом: попытки без вердиктов круга, попытки и вердикты без согласия с правилами.

Глобальной таблицы нет (ИР-009 п.7): в демо у Анны Глеб — 12 из заявленных 50, а у самого Глеба, чьи подписки — двое его фанатов, он первый с 50. Так и должно быть.

## 7. Клиент

```
bc contest create ТЕКСТ --unit ЕДИНИЦА [--better more|less] [--text-file ФАЙЛ]
bc contest adopt ПРАВИЛА                 копия правил к себе — тот же b2:…
bc contest join ПРАВИЛА                  согласие с правилами
bc contest round СОРЕВНОВАНИЕ [--name ТЕКСТ]
bc contest attempt РАУНД --video ФАЙЛ|b2:… [--claim N] [--from T] [--to T]
                   [--mirror ССЫЛКА …] [--note ТЕКСТ]
bc contest mirror ВИДЕО ССЫЛКА…          ещё копии видео
bc contest verdict ПОПЫТКА N [--from T] [--to T] [--note ТЕКСТ]
bc contest verify ФАЙЛ ПОПЫТКА --via URL тот ли это файл
bc contest show СОРЕВНОВАНИЕ --via URL   правила и раунды
bc contest table РАУНД --via URL [--hops 2] [--all]
```

`ПРАВИЛА`, `РАУНД`, `ПОПЫТКА` — `ЦЕПЬ/ХЕШ` блока; `СОРЕВНОВАНИЕ` — `b2:…` или `ЦЕПЬ/ХЕШ` правил. Пишущие команды выкладывают блок при `--via`. Лайкнуть или прокомментировать попытку — командами соцслоя на её `ЦЕПЬ/ХЕШ` (`bc social like`, `bc social comment`). Демо — `docs/pilot/contest-demo.sh`.

## 8. Чего нет

- Других сводок (среднее, лучший из N) и балла за технику — новыми видами и параметрами, без новых типов.
- Категорий (вес, возраст) и окна раунда по времени.
- Хранилища исходных файлов: где судье взять оригинал для проверки хеша — свой сервер, IPFS, торрент — пока забота спортсмена.
- Призов в трудочасах — и не будет: это беспричинный перевод (records.md §12.9).

## 9. Открытые вопросы

Решено при реализации — на пересмотр участнику:

1. Медиана при чётном числе судей — худшая для спортсмена из двух средних (contests.md §6).
2. Согласие требуется и от спортсменов, и от судей (contests.md §2).
3. Раунд открывает только тот, у кого в цепи копия правил (contests.md §3).
4. Таблица — по раунду; общей таблицы соревнования нет.
5. При равном итоге выше тот, у кого больше судей, потом — кто раньше.

Открыто:

6. Окно раунда — когда приём попыток закрыт.
7. Категории участников.
8. Где хранить исходные файлы для проверки хеша.
