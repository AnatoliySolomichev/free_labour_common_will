# Отзывы о продукции: товар под любым названием (ИР-026)

**Статус:** черновик v0.1 (2026-10-23).
**Назначение:** третий сценарий ИР-026 — отзывы о любой продукции по названию модели и по ссылкам магазинов — на той же заметке о предмете, что соцслой и соревнования (records.md §8.11, social.md §2). Нумерация разделов — своя (CLAUDE.md).

---

## 1. Назначение

Отзыв лежит в цепи автора, а не у магазина: магазин его не удалит и не спрячет, а сам отзыв идёт за товаром из магазина в магазин. У товара много названий — штрихкод, модель, ссылки разных магазинов; люди связывают их заявлениями «это тот же товар», и картина товара собирает отзывы со всех его названий. Глобального рейтинга нет (ИР-009 п.7): отзывы и склейки — глазами вашего круга.

Решения участника 2026-10-23:

- ключи товара — штрихкод, название модели и ссылки Ozon, Wildberries, Яндекс Маркета, Amazon, AliExpress (social.md §3.6);
- отзыв — звёзды от 1 до 5 и текст; у товара, сделанного в системе, — подтверждённая покупка (reviews.md §4);
- «тот же товар» склеивают ваши заявления и заявления круга; «не тот же» снимает своё и оспаривает чужое (reviews.md §3);
- пока один уровень: варианты товара (цвет, объём) — разные ключи.

Новых типов записей нет: вид `review` той же заметки и `same` из соревнований.

## 2. Отзыв

```
Note{ about: "gtin:04601234567893", kind: "review", v: 4, text: "держит заряд два дня" }
```

- `about` — товар под любым его названием: ключ (social.md §3.6) или блок записи труда — товар, сделанный в системе (ИР-023).
- `v` — звёзды, от 1 до 5; `text` — сам отзыв, по желанию.
- **Последнее слово автора** (records.md §8.11): правка — новый отзыв. Если автор писал о товаре под двумя названиями, действует последний отзыв.
- **О своём товаре отзыв не пишут:** у товара из системы автор отзыва не может быть его мастером — своя подпись ничего не добавляет (как пломба, records.md §8.9).
- **«Полезно»** — реакции круга на сам отзыв (`bc social like ЦЕПЬ/ХЕШ-отзыва`, social.md §4).

## 3. «Тот же товар»

```
Note{ about: "ozon:123456789", kind: "same", re: "gtin:04601234567893" }          тот же
Note{ about: "ymarket:1779337045", kind: "same", v: 0, re: "gtin:04601234567893" } не тот же
```

- Заявление — не слияние: каждый применяет чужие заявления сам, как `same_as` у оси (records.md §11.12). Связь симметрична: агрегатор показывает заявление и тому, кто смотрит на второе название (social.md §7).
- `v` — 1 (тот же, по умолчанию) или 0 (не тот же); у каждого действует последнее слово о паре названий. «Не тот же» снимает своё заявление и оспаривает чужое.
- **Склейку решают ваши заявления и заявления вашего круга** (social.md §5). Ваше слово решает само. В круге «тот же» без «не тот же» — склейка; и то и другое — **разногласие**: картина его показывает, а названия не склеивает. С `--all` в счёт идут заявления всех — так видно, зачем круг.
- Склейка идёт по цепочке: модель = Ozon, Ozon = штрихкод — значит, модель = штрихкод.
- Один уровень: «тот же товар» склеивает названия одного товара. Варианты — чёрный и белый, 128 и 256 ГБ — разные ключи; связь «вариант модели» — потом (reviews.md §7).

## 4. Подтверждённая покупка

У товара, сделанного в системе, есть запись труда с серийником (ИР-023), а покупка — это перевод с приёмкой этой работы (records.md §9.5). Отзыв ссылается на свою сделку вторым предметом:

```
Note{ about: <запись труда: табурет>, kind: "review", v: 5, re: <своя сделка покупки> }
```

`bc review add` находит сделку в ваших ветках сам. Картина пишет «покупка подтверждена», если:

1. сделка лежит в цепи автора отзыва и платит он сам;
2. её приёмка называет именно эту работу;
3. по ней ушли часы — состояние сделки у агрегатора (`GET /deal`) из тех, что двигают часы (records.md §13).

Подделать такой отзыв можно только настоящей покупкой (ИР-024). Отзыв без сделки показывается с пометкой «без сделки покупки», но считается: подтверждение — сигнал, а не пропуск, как заверенность (records.md §12.11). У товара вне системы покупку не подтвердить — вес отзыву даёт только круг.

## 5. Картина товара

`bc review show ТОВАР` — с любого названия:

- **он же** — все названия товара по склейке (reviews.md §3); **разногласия** — отдельно, с именами;
- **отзывы круга** — по последнему слову каждого: число, медиана звёзд (при чётном числе — меньшая из двух средних) и раскладка по звёздам;
- каждый отзыв: звёзды, дата, автор, текст, под каким названием написан, «покупка подтверждена» или «без сделки покупки», «полезно» от круга;
- **вне круга** — только числом, «со слов агрегатора».

## 6. Клиент

```
bc review add ТОВАР --stars N [ТЕКСТ] [--deal ЦЕПЬ/ХЕШ]
bc review same ТОВАР ТОВАР [--no]
bc review show ТОВАР --via URL [--hops 2] [--all]
```

`ТОВАР` — ссылка магазина, штрихкод (можно голыми цифрами), `gtin:…`, `"model:название"`, `ozon:…`, `wb:…`, `ymarket:…`, `amazon:…`, `ali:…` или `ЦЕПЬ/ХЕШ` записи труда. Пишущие команды выкладывают блок при `--via`. Ключ любой ссылки покажет `bc social key`. Демо — `docs/pilot/review-demo.sh`.

## 7. Чего нет

- Уровней «модель → вариант → экземпляр»: связь «вариант модели» и сводка отзывов вариантов в картине модели.
- Своих правил для других магазинов — пока `url:`.
- Фото к отзыву — так же, как видео попытки: ключ `b2:` по хешу файла и копии (contests.md §4).
- Отзыва о продавце, а не о товаре, — это ИР-024 («стал бы иметь дело снова»).

## 8. Открытые вопросы

Решено при реализации — на пересмотр участнику:

1. Отзыв без подтверждённой покупки у товара из системы считается наравне, с пометкой (reviews.md §4).
2. Медиана звёзд при чётном числе отзывов — меньшая из двух средних (reviews.md §5).
3. «Ё» в названии модели читается как «е»; знаки, а не буквы, — граница слов (social.md §3.6).
4. Склейка по цепочке не ограничена глубиной, но названий — не больше 64 на картину.

Открыто:

5. Уровни «модель → вариант».
6. Вес отзыва по истории автора (сколько отзывов подтверждено покупкой) — сейчас только пометка у каждого.
